Accessibility and comfort¶

Sugar aims to make computing understandable through clear shapes, consistent placement, and direct feedback. Accessibility is part of that design, not an extra mode reserved for a few users.

Readable screens¶

Use the Activity View toolbar to zoom text or restore the original size. Help uses a high-contrast dark theme with generous spacing. If text still feels small, increase the Activity zoom before changing the desktop resolution; zoom keeps controls and images usable together.

Icons should have a tooltip or accessible name. A symbol alone is not enough when a learner cannot see its shape or has never encountered it before.

Keyboard and focus¶

A visible focus ring tells you where Enter, Space, or arrow keys will act. Move through controls with Tab and Shift-Tab, activate a selected control with Enter or Space, and use Escape to close a temporary palette. Activities should provide a logical focus order and should not trap focus in a decorative widget.

The Frame, Home, and Activity controls should remain reachable without a mouse. If a hardware keyboard has different labels, use the tooltip and the current Activity toolbar as the source of truth.

Speech and selected text¶

Select text in Help or another text Activity, open the Frame, and choose the speech control to have it read aloud. Short selections are easier to follow; headings and paragraphs can be read separately. If speech is unavailable, the text remains available for copy, Journal storage, or another reader.

Color and collaboration¶

Color is expressive in Sugar, but it should not be the only signal. Good Activities pair color with a label, shape, position, or tooltip. In shared Activities, participant presence should be represented by names or icons that remain distinguishable without relying on color alone.

Reduced motion and calm use¶

Transitions should communicate a change of view, not compete with the work. When a learner is distracted or motion-sensitive, prefer a stable view, close extra palettes, and keep one Activity visible at a time. The Frame provides a calm way to check status without opening overlapping windows.

Support conversations¶

Ask what the learner can see, hear, and reach. Confirm whether the problem is content, focus, contrast, network access, or a stopped Activity. Small concrete observations lead to better fixes than assuming that every difficulty is a user error.
